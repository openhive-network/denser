# Performance work 2026-10-06/07: results

Follow-up to the October audit (`page-audit-2026-10.md`, #1039) and the logged-in
measurement (`logged-in-2026-10-07.md`). This records what changed between the audit's
baseline and the integration site after the last promote of this round.

## Method

- Site: https://denser.discuss.peerverity.info, `aidev/integration`, live Hive API.
- The integration Lighthouse check (`stack/integration/lighthouse.sh`): mobile, simulated
  throttling, median of the runs per route.
- **Before:** `390e5d31` (2026-10-06 04:37 UTC), 3 runs per route, logged out only.
- **After:** `03db663e` (2026-10-07 06:12 UTC), 5 runs per route (#1064), logged out and
  logged in (#1066). The check's environment probes (#1060) classified the pass as
  `normal`.
- *Simulated LCP* is what Lighthouse scores. *Observed LCP* is when the browser actually
  painted (#1064). The check only records it from `03db663e` on.
- Script bytes are transfer sizes. Before, assets were compressed on the fly (gzip/zstd).
  After, they're precompressed brotli (#1068), and part of the drop comes from that.

## Server side

- **SSR memory leak fixed (#1069).** Every server render that rendered `useRebloggedByQuery`
  scheduled a 1-hour React Query GC timer, which on Node 24 retained the whole request
  (its `ServerResponse`, query data and everything fetched). Production build, 1,000-request
  chunks over 5 routes, forced full GC:

  | requests | heap used before | heap used after #1069 |
  |---|---|---|
  | 0 | 86 MB | 86 MB |
  | 1,000 | 393 MB | 112 MB |
  | 2,000 | 671 MB | 112 MB |
  | 3,000 | 950 MB | 113 MB |
  | ~6,500 | out of memory | |

  Before, nothing was released after 6 minutes idle. A guard now stops every server
  `QueryClient` from scheduling GC timers, and the deterministic Lighthouse suite checks
  heap growth over 1,000 renders.
- **`compress: false` stays (#886).** Retested on Next 16 / Node 24: with `compress: true`,
  ≈45 KB per response of ArrayBuffers is still retained. Compression belongs in the proxy.
- **Profile reads are cached for anonymous visitors (#1047):** repeat loads of `/@gtg`
  render in tens of milliseconds, against 230–520 ms.

## Delivery

- **Follow mode (#1056):** the integration site builds `aidev/integration` from source and
  rebuilds only the app a commit changes, serving the old build until the new one is up. A
  promote takes ~2 min (was 15–20 min with image builds), and the site updates ~1 min later.
- **Precompressed static assets (#1068):** `/_next/static` is served by Caddy as brotli or
  zstd. The wax WASM is 754 KB (was 983 KB gzip); initial JS is ~17% smaller than on-the-fly
  compression. Earlier releases' chunks stay available after a swap, and static responses no
  longer carry cookies.
- **Reproducible builds (#1062):** Sentry's after-compile hook rewrote `node_modules`, so
  rebuilds in place shipped ~12 KB more JS. It's off now, and builds of the same tree are
  byte-identical.
